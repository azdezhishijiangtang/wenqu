# 问渠 · 高中理科 AI 答疑

> 面向高中数学、物理、化学、生物的 AI 答疑与学习工作台。带图片题识别、错题本、学习计划与知识手册，全部功能在浏览器里完成。

**在线使用：** https://azdezhishijiangtang.github.io/wenqu/
（本应用同时部署在「格致」门厅的高中区：https://azdezhishijiangtang.github.io/gezhi/highschool/ ，两者是同一套代码。）

> **本站是纯前端静态应用：没有后端、没有账号体系、不收集任何数据、没有任何第三方统计脚本。**
> 解题用的 API Key 由你自己填写，只保存在当前浏览器；图片文字识别由浏览器本机的 Tesseract.js 完成，原图不上传。

## 它能做什么

| 模块 | 说明 |
|---|---|
| **四科 AI 答疑** | 数学 / 物理 / 化学 / 生物，三种回答模式：**启发式**（引导你自己想）、**完整讲解**（逐步推导）、**应试速解**（直奔得分步骤）。回答流式输出，推理过程可折叠。 |
| **图片题** | 粘贴或上传最多 3 张题图 → 浏览器本机 OCR 提取文字 → **你人工核对修改** → 再交给文字模型解答。 |
| **知识手册** | 四科公式与规律速查，支持按科目筛选、一键复制 LaTeX。 |
| **错题本** | 记录题目、错因、正确思路与掌握状态，可以「带着错因再问 AI」。 |
| **学习计划** | 按周任务、完成统计，内置 25 分钟专注计时器。 |
| **数据备份** | 导出 / 导入 JSON 备份，用于换设备或在清理浏览器数据前搬家。 |
| **模型自动识别** | 填好接口地址和 API Key 后自动拉取该服务商当前可用模型（OpenAI 兼容 `GET /models`），拉取失败自动回退内置参考目录，也可以手动填模型名。 |

所有 AI 回答都以 Markdown + LaTeX 渲染，公式由 KaTeX 在浏览器本地排版，不请求外部公式渲染服务。

## 三步开始用

1. 打开在线地址，点设置里的 **「API 设置」**。
2. 填 **接口地址**（如 `https://api.deepseek.com/v1`）、**API Key**（`sk-...`）、**模型名**（可点「获取可用模型」自动列出）。可先点 **「测试连接」** 确认能通。
3. 保存后回到主页提问即可。想拍题就点图片按钮上传题图，核对 OCR 文字后发送。

> 不想每次刷新都重贴 Key？见下一节的「解锁口令」。**不设也完全能用。**

## 接入你自己的 AI 模型

本站采用 **BYOK（Bring Your Own Key）**：浏览器直连你填写的服务商，不经过任何中间服务器。

| 项目 | 说明 |
|---|---|
| 接口协议 | OpenAI 兼容的 `/chat/completions`（SSE 流式）与 `/models` |
| 内置预设 | DeepSeek、智谱 GLM、Kimi、OpenAI 等常见服务商；也可选「自定义」填任意兼容地址 |
| 模型发现 | 依次尝试 `<地址>/v1/models` 与 `<地址>/models`；结果缓存 24 小时，可随时手动刷新 |
| 拉取失败时 | 显示**具体失败原因**（网络 / 401 / 429 / 5xx / CORS 等），并回退内置参考模型目录，不会卡住 |
| 地址要求 | 必须是 **HTTPS**（或 localhost）。浏览器会拦截 HTTPS 页面向 HTTP 明文地址发的请求，这是浏览器安全策略，前端无法绕过 |

常见问题：

- **提示 CORS 错误**：说明该服务商不允许浏览器跨域直连。请换用支持浏览器直连的服务商或它提供的跨域地址；纯前端无法代为解决跨域。
- **401 / 无效密钥**：检查 Key 是否复制完整、是否有多余空格、额度是否用尽。
- **429 / 限流**：稍后重试，或在设置里换一个模型。
- **测试连接超时**：默认 45 秒，网络较慢时属正常，可稍后重试。

## 密钥保护与「解锁口令」

设置弹窗下方的 **「密钥保护」** 面板，是本站保护你 API Key 的地方。里面的「口令」常被误解，请先看这三句话：

1. **API Key**（`sk-...`）是服务商给你的，用来让 AI 干活。
2. **解锁口令**是你自己随便设的（至少 8 位），只是给**浏览器里的临时保险箱**上锁用的本地密码。
3. **它不是网站密码**——本站没有账号、不用注册登录；**也不是 API Key**。

| 用法 | 效果 | 适合谁 |
|---|---|---|
| **不设口令（默认）** | Key 只存在内存里，刷新或关闭标签页立即消失；每次刷新要重新粘贴一次 Key | 最在意安全、公用电脑、临时用一次 |
| **设口令 + 点「会话内记住」** | 用 `PBKDF2-SHA256(310000 轮)` 派生 + `AES-256-GCM` 把 Key 加密后暂存在**当前标签页**；刷新后输口令「解锁」即可，不用重贴 Key | 自己的电脑，需要反复刷新 |

关键事实：

- 口令**哪里都不存**，网站没有服务器，口令从不进入任何网络请求，也**无法找回**（忘了就点「彻底清除」，重新粘贴 API Key 再设一个新口令即可，Key 本身没丢）。
- 明文 Key **永不写入** `localStorage`、Cookie、导出备份；保存的设置里只有一个不能发请求的句柄（`@byok-vault:...`）。
- 密文只写 `sessionStorage`，**关闭标签页即由浏览器清除**；最长 8 小时过期。
- 自动锁定：空闲 **15 分钟**、页面切到后台 **3 分钟**、刷新 / 关闭页面，都会清空内存里的明文。
- 面板右侧新增 **「?」按钮**，点开就是这套机制的白话说明（含常见问题与安全边界）。

> 📖 **看不懂这个口令到底在干什么？** 请读完整说明书： **[《密钥保护说明.md》](./密钥保护说明.md)**
> 里面有「三个东西别搞混」对照表、设 / 不设的对比、逐步操作、10 条常见问题（含「忘了怎么办」）、加密参数与如实的安全边界。

## 隐私与数据边界

| 数据 | 存在哪里 | 会不会离开你的设备 |
|---|---|---|
| 对话记录、错题本、学习计划、掌握状态 | 当前浏览器的 `localStorage`（键带 `wenqu-` 前缀） | **不会**，除非你自己导出备份文件 |
| API Key 明文 | **只在运行内存里** | 只会发往**你填写的那个服务商地址** |
| 加密暂存密文（仅设口令时） | 当前标签页的 `sessionStorage` | **不会** |
| 解锁口令 | 不存储 | **不会** |
| 图片原图 | 只在浏览器内存里做 OCR | **不上传**；只有你核对后的**文字**会发给解题模型 |
| 站点自身 | 无后端、无数据库、无账号、无埋点 | —— |

要点：

- 本站**没有服务器可以中转或保存**你的任何内容，请求由浏览器直接发给你配置的服务商。
- 清理浏览器数据会一并清掉对话和错题，**请定期导出备份**。
- 导出备份**永远不含 API Key 和口令**；换设备后需要重新粘贴 Key。
- 不要在公共电脑上保存密钥；用完点「清除密钥」/「彻底清除」并关闭标签页。

## 数据与备份

- **导出**：设置 → 数据 → 导出 JSON，得到一份可离线保存的档案。
- **导入**：在同一页面导入 JSON，会覆盖当前档案（导入前建议先导出一份）。
- 备份用于**换设备**、**清理浏览器数据前**、**换浏览器**；它不含密钥，所以导入后要重新填 API Key。

> 提示：高中区（`wenqu-`）与大学区（`mathlens-` / `principia-`）存储键前缀不同，同域下也互不干扰。

## 浏览器兼容性

目标是「纯前端、所有设备、所有浏览器」：

- 构建目标 `es2018`，兼容较旧的浏览器内核。
- 带兼容层：`fetch` 缺失时降级 XHR、`AbortController` polyfill、SSE / `ReadableStream` 降级、`TextEncoder/TextDecoder` 兜底。
- 隐私模式 / 禁用存储时自动降级到内存存储，页面仍可用（但刷新后数据不保留）。
- 部署了严格 CSP、`Referrer-Policy`，并禁用第三方可执行脚本。
- 移动端自适应；图片识别需浏览器支持 WebAssembly。

**无法由前端绕过的边界**：真实跨域限制（CORS）、网络屏蔽、HTTPS 页面请求 HTTP 地址被浏览器拦截。这些需要服务商或非前端方案配合。

## 本地开发

```bash
npm ci
npm run dev          # 本地开发服务器
```

构建与开发启动前会自动运行 `scripts/prepare-ocr.mjs`，从 npm 依赖复制 Tesseract Worker、WASM 引擎和中英文字库到 `public/ocr/`；资源随静态站点发布，运行时**不依赖第三方 CDN**。首次识别需加载这些资源，属正常现象。

```bash
npm run build        # tsc -b && vite build
npm run test:app     # 备份与存储的单元测试
npm run preview      # 本地预览构建产物
```

技术栈：Vite + React + TypeScript + KaTeX + Tesseract.js；无后端运行时依赖。

## 部署

推送到 `main` 后，`.github/workflows/deploy.yml` 会自动构建并把 `dist/` 发布到 GitHub Pages。构建产物是纯静态文件，也可部署到任意静态托管（Cloudflare Pages、Netlify、对象存储等）。

首次部署需在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。

部署注意：

- 站点以**相对路径**构建，放在 `/wenqu/` 这类子路径下也能正常加载（含 OCR 资源）。
- 请勿删除 `public/ocr/` 下的资源文件，否则图片识别会 404。
- 若自行加 CDN / 第三方脚本，需同步更新 CSP 白名单，否则会被浏览器拦截。

## 已知限制与安全边界

- **纯前端 BYOK 的不可能三角**：发请求那一刻浏览器必须短暂持有明文 Key。若页面被注入恶意脚本（XSS），攻击者仍可能在解锁期间读取。本机制把「长期磁盘明文」变成「短暂内存明文」，并配合严格 CSP 降低风险，但**不能宣称绝对不会泄露**。
- 请务必使用**额度受限、可随时撤销的专用子密钥**，不要用主账号密钥，并定期轮换。
- OCR 对印刷体、清晰图片效果最好；手写潦草、公式密集的图片需要你人工核对修正。

完整技术说明见 **[《密钥保护说明.md》](./密钥保护说明.md)**。
